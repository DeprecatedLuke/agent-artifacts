--- title: Writing reports description: The writing rules, every component with live examples, and the report:// workflow for publishing and editing artifacts reports. ---

An artifacts report is an HTML fragment or a GitHub-flavoured Markdown document in a store your reader can open, share for seven days, and watch update live. You write source; the server adds the header, the revision and the theme; this page is the whole style guide.

Rules

  1. Lead with the result. The first screen answers what happened and what the reader should do about it. Detail comes after.
  2. Every fact appears once. Do not repeat the description in the body; no recap, summary, "key takeaways" or conclusion. Never show the same data twice — not as table and chart, not as table and prose.
  3. Prefer visuals to paragraphs. Tables, charts, diffs and before/after images first; one visual per idea.
  4. Cut process. No "I first looked at…", no restating the task, no methodology unless it changes how far the result can be trusted, no hedging, no filler adjectives, no marketing tone.
  5. No footnotes. Cite sources as inline links next to the claim; mark uncertainty once, at the claim.
  6. No unicode symbols. Arrows, check marks, triangles, stars and emoji in text or attributes are rejected: write <x-icon name="check-circle"></x-icon> instead of a check mark (see Icons below). In math use \to and \Rightarrow.
  7. Numbers carry units and a baseline. Say what the number is compared against. Identifiers, paths and commands go in <code>.
  8. Shortest complete form. Detail that only some readers need goes in <details>.
  9. Edit in place. Rewrite the report; never append "Update:" sections. The header already shows the revision and time.
  10. Title is a specific noun phrase without the project name. Description is one or two sentences of scope plus outcome.
  11. Never write structure, styles or scripts for layout. Use the components below; they already handle theme, width and print.

Body format

The body is either an HTML fragment or GitHub-flavoured Markdown; the server tells them apart. Pick one per report and mix raw HTML into Markdown where a component is needed (x-chart, x-diff, x-tabs, x-metric, x-icon, figure, details). Markdown gives you headings, lists, pipe tables, blockquotes, links, images, inline code, fenced code with a language, and ```mermaid fences that render as diagrams. Markdown headings shift down one level (# becomes h2) because the page title is the only h1. Every other rule applies unchanged: no banned glyphs outside code, no external image URLs, no style attributes and no forbidden elements in raw HTML.

## Result

32/32 checks PASS; no source file changed.

A contents sidebar is built from the body's headings: the two highest levels present, at least three entries. It sits on the right of wide viewports and behind a toggle button on narrow ones, so never write a manual table of contents.

Text and math

Write ordinary HTML: p, h2, h3, ul, ol, table, aside, figure, details, blockquote, hr. Inline code uses <code>. Inline math uses $…$ or \(…\); display math uses $$…$$ or \[…\].

<p>Latency dropped to $p_{95} = 123\ \text{ms}$, a $4\%$ improvement.</p>
<p>$$\text{throughput} = \frac{N}{t}$$</p>

Live: latency dropped to $p_{95} = 123\ \text{ms}$, a $4\%$ improvement.

Icons

x-icon renders a Heroicons v2 20/solid icon inline, in the current text colour. name is any 20/solid name (browse the set at heroicons.com); tone is ok, warn, err, muted or accent; label gives the icon an accessible name, without it the icon is decorative and hidden from screen readers. Icons scale with the text and sit on the baseline, so they work in prose, headings, table cells and list items.

<p>Cache hit rate <x-icon name="arrow-trending-up" tone="ok" label="improved"></x-icon> 94%.</p>
<h3><x-icon name="check-circle" tone="ok"></x-icon> All routes healthy</h3>
<td><x-icon name="x-circle" tone="err" label="failed"></x-icon></td>

Live: cache hit rate 94%, p95 41 ms, deploy clean, rollback drill pending, build queued, notes muted.

Code

A <pre><code class="language-xxx"> block is highlighted in both themes. Every grammar Shiki bundles works (about 220), plus their aliases: sh, yml, ts, rs, py, dockerfile. Only the languages a report uses are downloaded. An unknown name renders as plain text.

<pre><code class="language-rust">fn main() {
    println!("hello");
}</code></pre>
fn main() {
    println!("hello");
}
cargo run --release

pre.mermaid is rendered as a diagram in the current theme: flowcharts (with labelled edges and arrowheads), sequence, class, state, ER, gantt and pie charts. Write Mermaid source as usual, indented under the fence. In Markdown a ```mermaid fence is the same thing. Clicking the diagram opens it fullscreen.

Charts

An x-chart holds a Vega-Lite (or Vega) JSON spec in a script payload. Every Vega-Lite chart type works: line, multi-series line, area and stacked area, bar, grouped and stacked bar, scatter, heatmap, layered views, facets and interaction (brush, legend toggle, tooltips). Colours, axes and tooltips come from the report theme; add tooltip encodings to get hover values. Data can be inline in data.values or loaded from data.url: "assets/name.csv". Expressions run in the interpreter, never with eval.

<x-chart>
  <script type="application/json">
  {
    "data": {"values": [
      {"day": "Mon", "p95": 132}, {"day": "Tue", "p95": 118},
      {"day": "Wed", "p95": 121}, {"day": "Thu", "p95": 96}
    ]},
    "mark": {"type": "line", "point": true},
    "encoding": {
      "x": {"field": "day", "type": "ordinal", "sort": null},
      "y": {"field": "p95", "type": "quantitative", "title": "p95 (ms)"},
      "tooltip": [{"field": "day"}, {"field": "p95", "title": "p95 (ms)"}]
    }
  }
  </script>
</x-chart>

Interactive: drag across the bars to brush a region; the legend and the brush drive the colour.

Diffs

x-diff takes unified diff text in a script type="text/plain" payload: old and new line numbers, red deletions and green additions with word-level highlights, a file header with the change size and syntax highlighting. mode="side" is side by side; the default is line by line. Several files can follow each other in one payload. The language comes from each file name in the ---/+++ headers; lang="rust" forces one grammar for every file.

<x-diff mode="side" lang="rust">
  <script type="text/plain">
--- a/src/app.rs
+++ b/src/app.rs
@@ -1,2 +1,2 @@
 fn main() {
-    old();
+    new();
 }
--- a/web/api.ts
+++ b/web/api.ts
@@ -1,1 +1,1 @@
-export const url = "http://localhost";
+export const url = location.origin;
</script>
</x-diff>

Tables

Tables get zebra striping and a sticky header. Add class="sortable" for click-to-sort on any column: numbers, file sizes, ISO dates and text sort correctly, and the sorted column shows a chevron. Put class="num" on numeric cells to right-align them; a cell that should sort by another value can carry data-sort="123". Every table carries an expand button that opens it fullscreen, a wide table takes the full page width rather than hiding columns, and inline code wraps inside cells, so no table needs trimming or splitting.

<table class="sortable">
  <thead><tr><th>Route</th><th class="num">p95 (ms)</th></tr></thead>

Callouts

aside is a callout: a tinted box with an even 1px border, a kind icon and a kind label. Classes note (default), ok, warn and error pick the colour, icon and label.

<aside class="warn">
  <p>Share links expire after seven days.</p>
</aside>

Publishing validates the document; a rejected write returns 422 with line numbers.

Every check passed: all 12 routes stayed below the 250 ms p95 budget.

Share links expire after seven days. There is no way to extend one.

Validation rejected the last write: the body contained a unicode arrow.

Figures

A figure pairs an image with a caption. Images must be assets/<name> (uploaded with the report_upload tool) or a data: URI; external URLs are rejected. Clicking an image opens it fullscreen.

<figure>
  <img src="assets/graph.png" alt="Latency by region">
  <figcaption>Latency by region, baseline is the previous release.</figcaption>
</figure>

Details

details folds detail that only some readers need.

<details>
  <summary>All 312 sample timings</summary>
  <p>…</p>
</details>
All 312 sample timings

Folded content keeps the main line short. Put raw data, full logs or long derivations here.

Grids

x-grid lays children out in responsive columns: cols="2", "3" or "4", collapsing on narrow screens.

<x-grid cols="2">
  <figure>…</figure>
  <figure>…</figure>
</x-grid>

Metrics

x-metric is a stat card: label, value, optional delta and a trend of good, bad or neutral (default).

<x-metric label="p95" value="123 ms" delta="-4%" trend="good"></x-metric>

Tabs

x-tabs turns section title="…" children into tabs. Use them for alternative views of the same object, not for sequential reading.

<x-tabs>
  <section title="Summary"><p>…</p></section>
  <section title="Raw"><pre><code>…</code></pre></section>
</x-tabs>

Publishing with report://

Reports live at report://<project>/<slug>; the project is normally the name of your working directory.

  • report://myproj/p95 reads the editable source of report p95 in project myproj; edit and write work on the same URL.
  • report://myproj/p95.md is the read-only text version, for cross-referencing.
  • report://list lists the reports of the current project; report://list?project=other lists another project, ?project=* all of them.
  • report://guide always resolves to this page.

Writing the same URL creates the report if it does not exist and replaces it if it does; the revision increments and every open viewer updates over the websocket. Use edit with hashline patches to change part of a document, and write to create or replace it whole. Both validate first: a rejection lists the problem and the line.

---
title: p95 latency after the cache change
description: Cache hit rate went from 61% to 94%; p95 fell 123 ms to 41 ms with no error-rate change.
---
<x-metric label="p95" value="41 ms" delta="-67%" trend="good"></x-metric>

Images are uploaded with the report_upload tool, which stores them under the report's assets/ directory and returns the assets/<name> path to reference from an img.

The body is capped at 5 MiB. Inline script without src runs in the sandbox; external scripts, stylesheets, inline style attributes and remote images are rejected by validation.
